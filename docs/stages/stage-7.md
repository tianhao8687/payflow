## 3. Key design decisions

- `payment-core` is a zero-framework, zero-database, zero-provider-SDK contract
  package.
- The interface includes all required operations: create/query, optional
  capture/cancel, refund, and webhook verification.
- Stripe field mapping, status normalization, API calls, request IDs, error
  mapping, signature verification, and Event interpretation live together in
  `payment-stripe`.
- Business services inject the core symbol. Only one NestJS composition module
  imports the Stripe implementation.
- Stable idempotency keys continue to be generated by business repositories and
  passed unchanged to the adapter.
- Provider events become normalized actions before persistence/domain logic.
- ESLint import restrictions make the architectural boundary executable.
- The installed Stripe 22.5.0 TypeScript API supports the required hosted
  Checkout, PaymentIntent, Refund, and asynchronous Event-verification calls;
  no core stack or domain-model substitution was needed.

## 4. Actual code changes

- Added `PaymentProvider`, capabilities, normalized payment/refund statuses,
  webhook action union, results, and `PaymentProviderError`.
- Implemented `StripeProvider.createPayment`, `getPayment`, `capturePayment`,
  `cancelPayment`, `refundPayment`, and `verifyWebhook`.
- Rebound Payments, Refunds, and Webhooks services to `PAYMENT_PROVIDER`.
- Generalized payment/refund reservation and webhook persistence methods to
  receive provider identity rather than hard-code gateway classes.
- Preserved all advisory locks, idempotency keys, unique constraints,
  transaction boundaries, explicit domain state machines, and API DTOs.
- Updated workspace, Docker, development, test, and CI build order for the new
  packages.
